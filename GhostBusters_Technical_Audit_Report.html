GhostBusters: Read-Only Technical Audit

Prepared for AI competition pitching • Audit scope: source, configuration, tests, API routes, frontend, integrations, fixtures and infrastructure files • 30 July 2026

Bottom line. GhostBusters is a safety-first cloud-cost investigation and Terraform PR-review application. Its strongest complete demonstration is a fixture-backed review workflow that collects evidence, computes alternatives/confidence/policy, requires human review, and produces a simulated PR. Real GitHub/AWS/Jira paths are implemented but optional and credential-dependent. It never applies Terraform, merges PRs, deploys cloud resources, or auto-approves changes.

1. Current project truth

The application is a FastAPI web app with a static browser UI. A user may start a fixture scenario through POST /api/runs, submit a high-level goal through /api/goals, run a Cloud Hunt, or receive an allowed GitHub pull-request webhook at POST /webhooks/github.

  1. Terraform fixture plan JSON or GitHub PR diff is parsed (integrations/terraform_parser.py, integrations/terraform_runner.py).
  2. core/planner.py selects registered evidence tools; optional AI may propose bounded next tools.
  3. core/investigator.py collects evidence; core/reasoning_engine.py builds alternatives, conflicts, confidence, verifier results and policy result.
  4. Recommendation-ready cases stop for permissioned human review at /api/runs/{run_id}/review.
  5. Approval creates simulated PR data by default (core/mock_pr.py). With explicit GitHub configuration, integrations/remediation_pr_service.py can create one restricted remediation branch/file commit/PR.

Nothing is approved by AI, merged, deployed, or applied automatically. The non-demo connected-goal path (WorkflowService.start_connected_goal) is read-only and often ends as needs_more_evidence or abstained, rather than producing a full remediation.

3. Autonomous-agent analysis

Assessment: bounded, safety-constrained AI-assisted investigation—not a general autonomous cloud-operations agent.

QuestionAnswer and source evidence
Accept a high-level goal?Yes. /api/goals/validate and /api/goals accept text, scope, repositories, constraints and criteria.
Create a plan / select tools?Partially. AIPlanner.plan() and GeminiGoalPlan can propose; core/planner.py and allowlists are authoritative.
Change plan from evidence?Partially. The loop chooses next registered tools and can request human context; it cannot invent tools, permissions or mutations.
Handle ambiguity/request information?Yes. Deterministic percentage-target questions and optional AI clarifications in /api/goals/validate; request_human_context action exists.
Generate/select alternatives?Yes. alternative_generator.py creates downsize, schedule, keep, request-evidence, abstain/blocked options; _select_preferred ranks them.
Recover/fail safely?Yes. RetryExecutor retries transient failure and records classified, safe outcomes.
Stop on low confidence?Yes. Default threshold is 0.70; Rego/Python policy blocks remediation.
Dynamic or hard-coded order?Both: bounded dynamic tool selection within a largely hard-coded deterministic safety pipeline.
AI vs deterministic decisions?AI: interpretation, optional validation/plan/next-tool/explanation. Deterministic: parsing, allowlists, evidence execution, alternatives, conflicts, confidence, verifier, policy, eligibility. If/else: production/destructive/data-mode gates and action preference.

6. Human-in-the-loop and safety

  • Approval is mandatory for a remediation action: /api/runs/{run_id}/review, core/human_review.py.
  • Supported human actions: approve, reject, modify, request evidence, add context, revoke approval and reopen; Cloud Hunt additionally supports waiver.
  • Approval records idempotency, state version, actor snapshot and audit/activity event (human_decision_events, audit_log, activity_events).
  • Production, destructive changes, active dependencies, missing critical evidence and confidence below 0.70 are blocked by ghostbusters.rego and fallback policy.
  • RemediationPRService.create() separately rejects destructive/replacement/production/dependency/missing-evidence/ambiguous code changes.
  • No AI approval, automatic merge, deployment, Terraform apply, rollback or cloud mutation exists.

9. Live demo readiness

  1. Create and activate the expected .venv; install requirements.txt.
  2. Set DEMO_MODE_ENABLED=true; start uvicorn app.main:app --reload.
  3. Open http://127.0.0.1:8000; register; open Demo Readiness.
  4. Run the safe scenario; show Terraform parsing, labelled fixture evidence, policy, confidence and recommendation.
  5. Approve it; describe the resulting simulated PR truthfully.
  6. Run conflicting and missing_evidence; show conflict penalty and safe escalation.
  7. Close with Activity Log/Technical Audit.
Reliability. The fixture path is the strongest 5–7 minute demo, as documented in DEMO_GUIDE.md. Real GitHub/AWS/Jira/Gemini depend on credentials, permissions, network and preflight. run_demo.ps1 assumes an existing virtual environment. During this audit, tests could not be run because neither pytest command nor the Python pytest module was installed in the current environment.

12. Contradictions resolved

  1. Goal-driven vs PR-triggered: both; PR-review/fixture is most complete, goals are partial read-only workflows.
  2. Human vs AI approval: human approval mandatory; automatic AI approval absent.
  3. PR creation vs automatic merge: optional real PR creation; no merge.
  4. Recommendation vs deployment: recommendation/PR only; no deployment.
  5. LangGraph specialist agents: no LangGraph or named specialist-agent architecture found.
  6. Gemini-only: Gemini, optional Groq and mock client; no OpenAI provider.
  7. Real vs mock AWS: both; real AWS optional, fixture demo default.
  8. Project management: real Jira read-only path plus fixture Jira context.
  9. Fixed vs dynamic: bounded dynamic selection inside a deterministic safety pipeline.
  10. Dashboard vs goal-driven: dashboard-centered UI with both goals and PR-review entry points.

13. Claims for the presentation

Safe claims

  • Evidence-backed, policy-checked cloud optimization recommendations with an auditable trail.
  • Mandatory human approval before remediation PR generation.
  • Safe blocking for production, destructive changes, dependencies, critical missing evidence and low confidence.
  • Optional read-only GitHub, AWS, Jira and AI-provider integrations.

Claims requiring careful wording

  • “Autonomous investigation” → say “bounded, allowlisted AI-assisted investigation.”
  • “Creates PRs” → say “simulated PR in demo; optional real GitHub PR after explicit configuration and human approval.”
  • “Multi-cloud” → fixtures span AWS/Azure/GCP; real discovery is AWS-only.
  • “Savings” → live AWS path exists, but demo values are fixtures.

Do not claim

  • Autonomous deployment, Terraform apply, automatic merging, automatic approval, rollback, Cost Explorer, Linear/GitLab/Slack/Teams, infrastructure graph, real Azure/GCP operations, verified production savings, accuracy, test coverage or multiple independent agents.

15. Final executive summary

GhostBusters truly is a polished, safety-first cloud-cost investigation and Terraform PR-review platform. Its strongest competition differentiator is the combination of evidence-aware recommendations, abstention, policy gates, mandatory human approval and a visible audit trail.

Strongest live demonstration: the fixture-backed safe recommendation followed by conflicting and missing-evidence cases, with source-mode labels visible.

Three strongest implemented capabilities: deterministic safety evaluation; transparent decision/audit experience; optional guarded GitHub/AWS/Jira integration paths.

Three largest limitations: fixture/simulated core demo; incomplete goal-to-remediation automation; no apply/merge/deploy, Cost Explorer, infrastructure graph or real Azure/GCP support.

Presentation correction required: remove any implication of autonomous deployment, automatic approval/merge, Cost Explorer, real multi-cloud monitoring, or multiple independent agent roles.
